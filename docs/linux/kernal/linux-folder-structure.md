# 目录名称

理解 Linux 目录结构的命名和用途是掌握系统管理的重要一步。这些名称大多是英文单词的缩写，其结构遵循 FHS（文件系统层次结构标准） 的规范。

下面我将为您详细解读这些常见的目录名称及其含义。

核心原则：缩写与含义

大多数目录名称都是英文单词的缩写，通常是去掉元音字母后保留辅音形成短小精悍的名字（例如 lib from library）。

---

目录详解（从根目录 / 开始）

1. /bin - Binary

- 含义：二进制可执行文件。
- 内容：包含所有用户（包括超级用户和普通用户）都需要使用的、最基础的必要命令。这些命令在单用户模式或系统修复时也必须可用。
- 例子：ls, cp, mv, rm, cat, bash, echo。
- 注意：在现代系统中，/bin 通常是 /usr/bin 的一个符号链接。

2. /sbin - System Binary

- 含义：系统二进制文件。
- 内容：存放系统管理所需的关键命令，通常需要 root 超级用户权限才能执行。这些命令用于系统启动、修复和恢复。
- 例子：fdisk（磁盘分区）, ifconfig（网络配置）, reboot, shutdown, iptables（防火墙）。
- 注意：类似地，/sbin 现在也通常是 /usr/sbin 的符号链接。

3. /lib - Libraries

- 含义：共享库文件。
- 内容：为 /bin 和 /sbin 目录下的二进制程序提供必要的共享库（类似于 Windows 中的 DLL 文件）和内核模块。
- 衍生：
  - /lib64：在 64 位系统上，用于存放 64 位的共享库。

4. /usr - User (不是 "user" 的直译，历史含义是 User System Resources)

- 含义：用户系统资源。这是另一个非常重要的层级，包含大部分用户应用程序和文件。
- 内容：其下也有 /usr/bin, /usr/sbin, /usr/lib 目录，它们与根目录下的对应目录功能类似，但包含的不是系统最核心的命令，而是更丰富的应用程序和工具。
  - /usr/bin：非必要的、大部分用户使用的应用程序命令（如 vim, git, python）。
  - /usr/sbin：非必要的系统管理命令。
  - /usr/lib：为 /usr/bin 和 /usr/sbin 中的程序提供库文件。
  - /usr/share：架构无关的共享数据，如文档、图标、字体、时区数据等。
  - /usr/local：本地安装的软件。这是你手动编译安装的软件默认的安装位置，以防止其与系统自带的包管理器（如 apt, yum）管理的软件发生冲突。

5. /etc - Et Cetera (拉丁语，意为 “和其他”，引申为 配置文件目录)

- 含义：系统范围的配置文件。
- 内容：包含所有系统和应用程序的静态配置文件（文本文件），而不是可执行程序。
- 例子：/etc/passwd（用户账户）、/etc/hosts（主机名映射）、/etc/nginx/（Nginx 配置）。

6. /var - Variable

- 含义：可变数据。
- 内容：存放经常变化的文件，例如日志、缓存、假脱机文件（打印队列）、数据库等。
- 例子：
  - /var/log：系统日志和应用程序日志。
  - /var/cache：应用程序缓存数据。
  - /var/www：网站根目录（通常用于 Apache/Nginx）。
  - /var/lib：应用程序的状态信息（如数据库文件）。

7. /tmp - Temporary

- 含义：临时文件。
- 内容：供所有用户存放临时文件。系统重启后，此目录下的文件通常会被清除。

8. /home - Home

- 含义：用户家目录。
- 内容：每个普通用户都有一个以其用户名命名的子目录（如 /home/alice），用于存放其个人文件、配置文件（通常是点文件，如 ~/.bashrc）、文档、音乐等。root 用户的家目录是 /root。

9. /root - Root

- 含义：root 用户的家目录。注意它不是根目录 /，而是管理员的家目录。

10. /dev - Devices

- 含义：设备文件。
- 内容：包含所有的设备文件（块设备、字符设备），Linux 系统通过访问这些文件来操作硬件设备。
- 例子：/dev/sda（第一块硬盘）、/dev/null（空设备，丢弃一切写入的数据）、/dev/random（随机数设备）。

11. /proc - Process

- 含义：进程与内核信息。
- 内容：一个虚拟文件系统，它不占用磁盘空间，而是内核在内存中生成的，提供了访问内核进程信息的接口。里面的文件和目录对应着系统的运行状态。
- 例子：/proc/cpuinfo（CPU 信息）、/proc/meminfo（内存信息）。

12. /opt - Optional

- 含义：可选的应用软件包。
- 内容：通常用于安装那些独立的、第三方的大型商业软件或应用程序包（例如 Oracle Database, MATLAB）。所有相关文件都集中在同一个目录下。

---

补充目录详解

1. /boot - Boot

- 英文全称：Boot
- 中文释义：引导
- 用途：存放系统启动所必需的核心文件。这些文件在系统引导过程的最初阶段被读取，远在根文件系统被挂载之前。
- 包含内容：
  - 内核镜像（vmlinuz-*）：Linux 操作系统的核心。
  - 初始 RAM 磁盘镜像（initramfs-* 或 initrd-*）：一个临时的根文件系统，用于在真正根文件系统挂载前加载必要的驱动（如磁盘、文件系统驱动）。
  - 引导加载程序（Bootloader）文件：如 GRUB2 的相关文件（grub/ 目录）。
  - EFI 系统分区（ESP）：在 UEFI 系统上，通常也会将 ESP 挂载到 /boot/efi。
- 特点：这个目录下的文件通常是静态的，除非进行内核更新或引导配置更改。

2. /media - Media

- 英文全称：Media
- 中文释义：媒体（这里指可移动存储介质）
- 用途：可移动设备的自动挂载点。当您插入 U 盘、外部硬盘、SD 卡或光盘时，现代的 Linux 桌面环境（如 GNOME, KDE）会自动将这些设备挂载到 /media/<username>/<label> 目录下。
- 例子：插入一个名为 “MY_USB” 的 U 盘后，它可能会被自动挂载到 /media/your_username/MY_USB。
- 特点：自动、临时。由系统自动创建和管理目录。

3. /mnt - Mount

- 英文全称：Mount
- 中文释义：挂载
- 用途：临时手动挂载文件系统的挂载点。这是一个空目录，系统管理员可以临时在这里挂载任何块设备（如硬盘分区、网络共享、ISO 镜像文件）。
- 例子：
  - 手动挂载一个 Windows 分区：sudo mount /dev/sda3 /mnt（之后就可以在 /mnt 里访问它）。
  - 挂载一个网络共享（NFS）：sudo mount nas:/shared_data /mnt。
  - 挂载一个 ISO 文件：sudo mount -o loop ubuntu.iso /mnt。
- 特点：手动、临时。是系统管理员的一个通用“工作台”。与 /media 的自动化和用户级不同，/mnt 更偏向于管理员手动操作。

4. /srv - Service

- 英文全称：Service
- 中文释义：服务
- 用途：存放由本系统提供的服务所产生的或服务的特定数据。这是一个约定俗成的目录，用于让其他用户清楚地知道哪里可以找到特定服务的数据。
- 例子：
  - 如果这台机器是 Web 服务器，网站文件可以放在 /srv/http/ 或 /srv/www/。
  - 如果它是 FTP 服务器，FTP 的文件可以放在 /srv/ftp/。
  - 如果它是 Git 版本控制服务器，Git 仓库可以放在 /srv/git/。
- 特点：可选的，但强烈推荐遵循此规范，以便让系统结构更清晰。

5. /run - Run

- 英文全称：Run
- 中文释义：运行
- 用途：存放自系统启动以来的临时运行时数据，例如进程 ID（PID）文件、套接字文件、锁文件等。这些数据在系统重启后不需要保留。
- 包含内容：
  - .pid 文件：存放守护进程的进程 ID（如 /run/sshd.pid）。
  - 设备锁文件（如 /run/lock/lvm）。
  - 系统守护进程的通信套接字（如 Docker 的 /run/docker.sock）。
  - 早期启动过程和用户登录会话的信息。
- 特点：这是一个 `tmpfs` 文件系统，意味着它完全在内存中，读写速度极快，并且内容在每次重启后都会丢失。它取代了旧的 /var/run（现在通常是一个指向 /run 的符号链接）。

---


理解这些目录的命名和用途，能帮助您更好地管理 Linux 系统，知道文件应该放在哪里，以及在哪里找到您需要的东西。

## /etc
说得非常好！这是一个非常常见的问题。

/etc 确实是类 Unix 系统（如 Linux、macOS）中一个极其重要的目录，用来存放系统配置文件。

它是什么单词的缩写？

关于它的来源，有两种主流说法，都指向同一个含义：

1. 最主流和最初的说法：Etcetera（等等）
   - 在早期的 Unix 系统中，/etc 目录存放的是一些“杂项”文件，比如设备文件、系统维护工具等，而不仅仅是配置文件。它有点像“放各种零零碎碎东西的地方”，所以被命名为 etc，也就是 “et cetera”（拉丁文，意为 “and so on”, “and other things”，中文就是“等等”）。
   - 后来，随着操作系统的发展，越来越多的配置文件被集中放置在这个目录下，它逐渐演变成了专门存放静态的、不可执行的系统级配置文件的目录。虽然它的内容变得专一了，但这个历史悠久的名字却被保留了下来。
2. 后来的“回溯工程”解释：Editable Text Configuration（可编辑的文本配置） 或 Extended Tool Chest（扩展工具箱）
   - 这些是后人为了让它更符合现在的用途而创造的“反向缩写”。它们非常贴切地描述了目录的现代功能，但并非其命名的历史起源。这是一种“民间词源学”现象。

所以，最准确的说法是：`/etc` 是 “et cetera” 的缩写，意思是“等等”，源于其历史上存放杂项文件的用途。

现代 /etc 目录的特点：

- 系统级配置：存放的是影响整个系统或所有用户的配置，而不是单个用户的配置（单个用户的配置通常在用户家目录下，例如 ~/.config 或 ~/.ssh）。
- 静态文件：里面主要是文本文件，可以被管理员用文本编辑器（如 vim, nano）直接查看和编辑。
- 不包含二进制可执行文件：系统的可执行程序通常存放在 /bin, /sbin, /usr/bin, /usr/sbin 等目录。

常见例子：

你可以在 /etc 目录下找到许多重要的配置文件，例如：
```
- /etc/passwd：用户账户信息
- /etc/group：用户组信息
- /etc/hosts：主机名和 IP 地址的映射关系
- /etc/fstab：系统启动时自动挂载的文件系统列表
- /etc/ssh/sshd_config：SSH 服务器的配置
- /etc/nginx/nginx.conf：Nginx Web 服务器的配置（如果安装了的话）
- /etc/os-release：系统版本信息

```

总结

项目 说明
缩写来源 Etcetera（拉丁文，意为“等等”），因其最初是存放杂项文件的目录。
现代用途 存放系统级的静态配置文件。
常见误解 是 “Editable Text Configuration” 或 “Extended Tool Chest” 的缩写（这些是后人附会的解释）。

因此，当别人问起时，你可以说：“它本来是 ‘etcetera’ 的缩写，意思是‘放杂项的地方’，但现在我们专门用它来放系统的配置文件。”

## dev/sda 为什么是第一块硬盘
好的，这是一个非常核心且重要的概念！/dev/sda 代表第一块硬盘的原因源于 Linux 设备文件的命名规则。

简单来说，这个命名是 设备类型 + 序号 的组合。

---

1. /dev/ 部分

- `dev` 是 devices 的缩写。
- 这个目录包含了所有设备文件。在 Linux 的哲学中，“一切皆文件”，硬件设备也被表示为特殊的文件。对这些文件进行读写操作，就相当于在读写对应的硬件设备。

---

2. sd 部分

- `sd` 最初是 SCSI Disk 的缩写。
- SCSI（Small Computer System Interface）是一种历史悠久的磁盘接口技术协议。它的驱动程序架构非常稳定和成熟。
- 后来，更加常见的接口（如 SATA、SAS、USB）的磁盘也使用了这套相同的驱动程序框架。因此，内核将它们都识别为 sd 设备。
- 结论：今天，sd 基本上泛指所有使用 SCSI 子系统驱动的、通过块设备方式访问的硬盘。你机箱里常见的 SATA 硬盘、机柜里的 SAS 硬盘、以及你插上的 U 盘，都会显示为 sdX。

---

3. a 部分

- 这最后一个字母代表设备的顺序。
- 内核在启动过程中，会按照检测到磁盘的顺序，依次分配一个字母。
- 分配从字母 a 开始：
  - 第一块被检测到的硬盘就是 `sda`
  - 第二块就是 `sdb`
  - 第三块就是 `sdc`
  - ... 以此类推。

---

综合起来：/dev/sda

所以，/dev/sda 的意思就是： `/dev/` 目录下的、`sd`（SCSI/SATA/USB 等）类型的、第 `a`（第一块）硬盘。

---

更进一步：分区

一块硬盘通常会被划分成多个分区。分区的命名是在硬盘名称后面加上数字。

- /dev/sda1：第一块硬盘（sda）上的第一个主分区。
- /dev/sda2：第一块硬盘上的第二个分区。
- /dev/sda5：第一块硬盘上的第一个逻辑分区（通常分区号 1-4 留给主分区和扩展分区，逻辑分区从 5 开始）。

举例说明：

假设你的电脑有两块 SATA 硬盘和一个 U 盘，它们可能被这样识别：

设备文件 说明
```
`/dev/sda` 第一块 SATA 硬盘（系统主硬盘）
/dev/sda1 第一块硬盘上的 系统引导分区 (EFI)
/dev/sda2 第一块硬盘上的 根分区 (/)
/dev/sda3 第一块硬盘上的 家目录分区 (/home)
`/dev/sdb` 第二块 SATA 硬盘（数据盘）
/dev/sdb1 第二块硬盘上的第一个分区
`/dev/sdc` 第三块存储设备（U 盘）
/dev/sdc1 U 盘上的唯一分区
```

其他常见的设备前缀

- `hd`：IDE Disk 的缩写。这是更老的 IDE 接口硬盘的命名方式（如 hda, hdb）。在现代电脑上已经很少见。
- `nvme0n1`：NVMe Disk 的命名。用于更高速的 NVMe 协议固态硬盘（SSD）。
  - nvme0：第一个 NVMe 控制器
  - n1：该控制器下的命名空间（Namespace），通常是 1
  - p1：该硬盘上的第一个分区（例如 /dev/nvme0n1p1）
- `vd`：Virtual Disk 的缩写。常见于虚拟化环境（如 KVM 虚拟机）中的虚拟磁盘。

总结
```
部分 示例 含义
路径 /dev/ 设备文件所在的目录
设备类型 sd SCSI/SATA/USB 等类型的存储设备
设备序号 a 第一块被系统识别的该类型设备
分区号 1 该设备上的第一个分区
```
因此，`/dev/sda` 是第一块硬盘，因为它是由内核按照检测顺序分配的第一个 `sd` 类型的设备。

## NVMe
好的，我们来详细聊聊 NVMe。

这是一个在现代计算机，尤其是高性能台式机、笔记本和服务器中极其重要的技术。您看到的 nvme0n1 这样的设备名就是由它而来的。

1. NVMe 是什么？

- 全称：Non-Volatile Memory Express（非易失性内存 Express）
- 核心身份：它是一种通信协议或接口标准，专门为固态硬盘（SSD）设计，用于定义计算机如何与固态硬盘进行高速通信。

为了更好地理解，我们把它和它的前辈们做个对比：

---

2. 为什么需要 NVMe？—— 解决瓶颈问题

想象一下硬盘是一条路，数据是车：

1. SATA 接口（搭配 AHCI 协议）：
   - 这就像一条 乡村公路。它最初是为速度慢得多的机械硬盘（HDD）设计的。
   - 问题：即使你换上了一辆超级跑车（高速 SSD），但公路（SATA 接口）本身的速度上限（通常最高 600 MB/s）和交通规则（AHCI 协议）已经成了瓶颈，跑车根本发挥不出全力。
2. NVMe 接口（协议）：
   - 这就像为超级跑车（SSD）专门修建的无限速高速公路。
   - 设计初衷：它从零开始，专为闪存技术设计，充分利用 PCIe 总线的高带宽和低延迟。
   - 关键优势：直接连接CPU。传统的 SATA 驱动器需要通过各种控制器中转，而 NVMe SSD 通过 PCIe 总线直接与系统 CPU 通信，路径更短，延迟极低。
```
特性 SATA SSD (AHCI 协议) NVMe SSD (NVMe 协议)
设计初衷 为机械硬盘（HDD） 优化 为闪存介质（SSD） 从头设计
使用通道 SATA 通道（瓶颈明显） PCIe 通道（带宽极高）
最大队列深度 1 个队列，32 个命令 65535 个队列，每个队列 65535 个命令
延迟 较高 极低
理论速度 ~600 MB/s 可达数千 MB/s（例如 PCIe 4.0 x4 可达 ~8000 MB/s）
比喻 乡村公路 无限速高速公路
```
---

3. 如何识别 NVMe 硬盘？—— 设备命名规则

在 Linux 系统下，NVMe 硬盘的设备文件名与传统的 sda 完全不同，它遵循一个更具描述性的命名规则：

`/dev/nvme<controller_id>n<namespace_id>p<partition_id>`

我们以 `/dev/nvme0n1p2` 为例来拆解：

- `nvme`： 表明这是一个 NVMe 协议的设备。
- `0`： 控制器编号（从 0 开始）。这代表这是系统识别到的第一个 NVMe 控制器。如果你有两块 NVMe 硬盘，第二块就是 nvme1。
- `n1`： 命名空间编号（从 1 开始）。命名空间是 NVMe 标准中的一个功能，可以将一块物理硬盘划分为多个逻辑设备。对于绝大多数消费级 SSD，通常只有一个命名空间，所以总是 `n1`。
- `p2`： 分区编号（从 1 开始）。这代表该 NVMe 设备上的第二个分区。第一个分区就是 p1，第三个是 p3，以此类推。

所以，`/dev/nvme0n1` 指的是第一块 NVMe 硬盘的整体设备，而 `/dev/nvme0n1p2` 指的是这块硬盘上的第二个分区。

---

4. 物理形态：M.2 接口

- 一个重要区别：NVMe 是一种协议，而 M.2 是一种物理接口形态。
- 大多数 NVMe 硬盘都采用 M.2 接口（一种直接插在主板上的卡式接口，无需线缆）。
- 但是，并非所有 M.2 接口的 SSD 都是 NVMe 协议！ 有些 M.2 接口的 SSD 仍然使用旧的 SATA 协议，它们的速度会和 2.5 英寸的 SATA SSD 一样，并且它们在系统中会被显示为 `/dev/sda`（即 sdX 设备），而不是 nvmeX。
- 购买时务必确认：你要买的是 NVMe PCIe 协议的 M.2 SSD，而不是 SATA 协议的 M.2 SSD。

总结
```
项目 说明
NVMe 是什么 一种为固态硬盘（SSD） 设计的高速通信协议。
解决什么问题 解决了旧式 SATA/AHCI 接口对 SSD 性能造成的瓶颈。
核心优势 超高速度（利用 PCIe 总线）和极低延迟（直接连接CPU）。
设备文件名 在 Linux 中遵循 `/dev/nvme0n1p1` 格式，包含控制器、命名空间和分区信息。
物理形态 通常采用 M.2 接口（但注意区分 NVMe 协议和 SATA 协议）。
```
简单来说，NVMe 就是让现代固态硬盘性能全面释放的关键技术，也是当前高性能存储的绝对主流。

## 术语详解

1. NVMe
   - 英文全称：Non-Volatile Memory Express
   - 中文释义：非易失性内存 Express
   - 说明：这是一种专为固态硬盘（SSD）设计的高速通信协议（或称接口标准），用于替代老旧的 AHCI 协议。它充分利用 PCIe 总线的高带宽，实现极快的传输速度。
2. PCIe
   - 英文全称：Peripheral Component Interconnect Express
   - 中文释义：高速外围组件互联标准（通常简称 PCI Express）
   - 说明：这是计算机主板提供的一种高速串行扩展总线标准，用于连接显卡、固态硬盘、网卡等高性能硬件设备。NVMe 协议就是建立在 PCIe 总线之上的。
3. SSD
   - 英文全称：Solid-State Drive 或 Solid-State Disk
   - 中文释义：固态硬盘
   - 说明：使用闪存芯片（NAND Flash）来存储数据的存储设备，没有机械部件，其速度远快于传统的机械硬盘（HDD）。
4. SCSI
   - 英文全称：Small Computer System Interface
   - 中文释义：小型计算机系统接口
   - 说明：一套用于计算机和外部设备（如硬盘、磁带驱动器）之间连接和传输数据的标准集。Linux 系统中的 sd（如 sda）即源于此。
5. SATA
   - 英文全称：Serial ATtachment
   - 中文释义：串行 ATA
   - 说明：用于连接主板和存储设备（如HDD、SSD）的计算机总线接口，是并行 ATA（PATA）的继任者。


## HDD
HDD 是计算机存储领域一个非常基础且重要的术语。

HDD

- 英文全称：Hard Disk Drive
- 中文释义：硬盘驱动器，通常简称 机械硬盘 或 硬盘。

---

详细解释

HDD（Hard Disk Drive，硬盘驱动器）是一种非易失性的存储设备，这意味着即使在断电的情况下，它也能保留存储的数据。

它的核心技术是磁存储和机械运动：

1. 机械结构：一个典型的 HDD 内部包含一个或多个盘片（Platters），这些盘片由坚硬的材质（如玻璃或铝）制成，表面涂有磁性材料。盘片被固定在一个主轴上，由电机驱动以每分钟数千转的速度高速旋转（例如 5400 RPM 或 7200 RPM）。
2. 磁头：每个盘片的表面上方都有一个非常精密的磁头（Read/Write Head），其作用类似于老式唱片机的唱针，但它是悬浮在盘片上方而不直接接触。磁头负责读取和修改盘片上磁性物质的极性，以此来表示二进制数据（0 和 1）。
3. 工作方式：当需要访问数据时，磁头臂会移动到盘片的特定磁道（Track）和扇区（Sector）上方，等待盘片旋转到正确位置后进行读写操作。这个过程涉及物理运动，因此会产生延迟。

核心特点（与 SSD 对比）

特性 HDD (Hard Disk Drive, 机械硬盘) SSD (Solid-State Drive, 固态硬盘)
核心技术 磁存储，机械运动（盘片旋转、磁头移动） 闪存芯片（NAND Flash），纯电子操作
主要部件 盘片、磁头、主轴电机、磁头臂 控制芯片、闪存芯片（无任何活动部件）
速度 慢。受限于转速（RPM）和机械寻道时间。 极快。无寻道时间，延迟极低，读写速度是 HDD 的数倍甚至数十倍。
抗震性 差。运行时剧烈的震动或撞击可能导致磁头刮伤盘片，造成物理损坏和数据丢失。 好。没有活动部件，更耐震动和冲击。
功耗与噪音 较高。电机旋转和磁臂移动会产生噪音、发热和功耗。 低。几乎静音，发热量和功耗都更低。
容量与价格 容量大，单价低。每GB的成本远低于 SSD，适合存储大量数据。 容量相对小，单价高。每GB的成本高于 HDD。
形态 通常是 3.5英寸（台式机）或 2.5英寸（笔记本）的带外壳的盒子。 形态多样：2.5英寸、M.2、mSATA 等。

总结与应用场景

- HDD（Hard Disk Drive，机械硬盘）因其容量大、价格低廉的优势，至今仍然是大容量数据存储（如文件服务器、视频资料库、备份盘）的首选。
- SSD（Solid-State Drive，固态硬盘）则因其极快的速度、抗冲击性和静音等特性，已成为安装操作系统、应用程序和游戏以提升系统响应速度的绝对主流。

在现代计算机中，一种非常常见的配置是：

- 一块较小的 NVMe SSD（如 /dev/nvme0n1）用于安装系统和常用软件，保证极速启动和运行。
- 一块较大的 HDD（如 /dev/sda）用于存储文档、照片、视频等大容量数据。
